## Failures

- No errors, rejected connections, or tracebacks in any `launcher*.log` / `redis.log`. No failure point was reached up to N=100K.
- Expected, not a regression: teardown hit the 30 s `--teardown-timeout` for every echo run with N >= 10K, with Redis at 100% CPU (the O(N²) `SCAN` in `terminate`).
  N=1K tore down in 4.3 s and broadcast N=1000 in 5.2 s.

## Differences from the laptop

1. **Connections match the fix everywhere.** Every run is N + 32(P+1) plus a small constant of about one connection per process (7 / 19 / 67 at P = 4 / 16 / 64).
   The constant does not grow with N or with broadcast peers. No run is noticeably above the predicted bound.
2. **Launch is about 3.5x slower than the laptop** (24 s vs 7.1 s at 25K; 96 s vs 27 s at 100K), and it is not CPU-bound: launchers run at about 20% CPU each and Redis at about 24% during launch.
   Going from P=4 to P=16 halves launch time, but P=64 is no faster than P=16 (27.6 s) and its loop lag jumps to 17 s.
   So there is a per-node or shared limit near ~1K agents/s, not a per-launcher one. The cause is unidentified; next step is a `py-spy dump` of a launcher mid-launch.
3. **Echo throughput is about 1.28K/s, flat from 10K to 100K and across P = 4..64** (laptop about 2K/s at 25K, 1.4K/s at 100K).
   Throughput is bound by the single orchestrator; one EPYC core is slower than an M-series core. Redis sits at 20–28%.
4. **Broadcast N=1000 is faster (110 s vs 190 s) and Redis-bound:** Redis at 86% of a core, about 13 commands per message.
   On the laptop the launchers were the bottleneck.
5. Redis commands per echo rise from 13.0 (10K) to 18.2 (100K). Most likely this is the background heartbeat (TIME + SET every 30 s per agent) landing inside the longer echo phase, not extra per-message cost (not yet confirmed from commandstats).
6. Harness note: `run.sh` runs `ulimit -n 120000`, which also lowers the hard limit, so `maxclients` is capped at ~120K even though the node allows 600K. That blocks runs above ~119K agents.

Not run: TCP transport, py-spy CPU profile, stock academy-py 1.0 comparison venv.
